# Тест-план «Хлорис»

Статический сайт без сборки. Логика, где легко ошибиться (деньги и ввод пользователя), вынесена в чистые функции и покрыта автотестами. Остальное проверяется чек-листом перед выкладкой.

## Автоматически

| Что | Тип | Как запустить |
|---|---|---|
| Корзина (`js/cart.js`): добавление, количество от 0 до 20, суммы, доставка 350 ₽ до 5 000 ₽ и бесплатно от 5 000 ₽ или при самовывозе, очистка мусора из `localStorage`, формат цены | Unit, `node:test` | `node --test` |
| Поля формы (`js/validate.js`): имя, телефон (11 цифр, первая 7 или 8), комментарий до 500 знаков, пустой заказ | Unit, `node:test` | `node --test` |

Пробел: интерфейс (фильтры, корзина, форма, меню, слайдер) автотестами не покрыт. Следующий шаг при росте проекта — 4–5 сценариев на Playwright: фильтр + сортировка, добавление в корзину и оформление, пустой заказ, мобильное меню.

## Чек-лист перед выкладкой

Запустить `python -m http.server 5500`, открыть http://localhost:5500. Перед проверкой очистить корзину: DevTools → Application → Local Storage → удалить `chloris-cart`.

**Каталог**
- [ ] Сразу видно 8 карточек и кнопка «Показать ещё 8»; после нажатия видно 16, фокус на первой новой карточке.
- [ ] «Свадьба» — 4, «День рождения» — 5, «Без повода» — 7; «Свадьба» + «Моно-букеты» — «Пионовый вальс» и «Белое облако»; «В коробке и корзине» — 4.
- [ ] «Сначала дешевле» начинается с 2 200 ₽, «Сначала дороже» — с 7 900 ₽; Tab идёт по карточкам в том же порядке, что на экране.
- [ ] На телефоне фильтры — строка чипов с прокруткой, страница при этом не скроллится вбок.

**Корзина**
- [ ] «В корзину» дважды на одном букете: счётчик 2, уведомление «… в корзине», в корзине одна строка × 2.
- [ ] Минус, плюс, «Удалить» работают, фокус остаётся на той же кнопке или переходит на «Закрыть корзину».
- [ ] Букет за 3 900 ₽: «До бесплатной доставки — 1 100 ₽», доставка 350 ₽. Добавить ещё 1 100 ₽ — доставка бесплатная.
- [ ] Открытка без букета не остаётся: удалить последний букет — корзина пустая.
- [ ] Перезагрузить страницу — корзина на месте. Подменить `chloris-cart` на мусор — корзина пустая, ошибок в консоли нет.
- [ ] Esc и клик по затемнению закрывают корзину, фокус возвращается на кнопку корзины.

**Форма**
- [ ] «Ваш заказ» повторяет корзину; «Самовывоз» убирает доставку из итога.
- [ ] Пустая корзина и пустой комментарий: ошибка «Добавьте букет в корзину или опишите в комментарии…»; появилась позиция в корзине — ошибка исчезает.
- [ ] «Оформить» у тарифа подписки подставляет тариф в комментарий.
- [ ] Пустые имя и телефон — ошибки, фокус на имени. Телефон `+7 900 12` — ошибка про 11 цифр.
- [ ] Правильная форма: «Отправляем…», затем «Заказ принят» с суммой; корзина очищена.
- [ ] Офлайн (DevTools → Network → Offline): «Не получилось отправить заявку», форма и корзина остаются.

**Остальное**
- [ ] Слайдер отзывов: «Следующий» листает на одну карточку, на краях кнопки неактивны.
- [ ] Мобильное меню: открывается, пункт закрывает меню и ведёт к секции, Esc закрывает и возвращает фокус.
- [ ] Бегущая строка двигается только при прокрутке страницы; при «уменьшении движения» стоит на месте.

**Адаптив** — 320, 375, 768, 1024, 1440 px: нет горизонтального скролла, каталог 2/2/3/4/4 столбца, корзина на телефоне на всю ширину.

**Доступность**
- [ ] Весь сайт проходится Tab, контур фокуса виден везде; внутри открытой корзины фокус не уходит на страницу.
- [ ] Экранная читалка (NVDA или VoiceOver): после фильтра звучит «Показано N букетов…», у кнопки корзины — «Корзина, N товаров», у отзывов — «Оценка 5 из 5».

**Без JS** (DevTools → Disable JavaScript): видны все 16 карточек со ссылками «Заказать», нет кнопки корзины, фильтров и состава заказа, у пустой формы срабатывает нативная проверка браузера.

**Производительность**: CLS = 0; на телефоне грузятся `hero-800.webp` и карточки `-400`; вся страница меньше 1,5 МБ.
